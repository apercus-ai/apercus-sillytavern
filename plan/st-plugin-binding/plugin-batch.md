## 0. 目标 / 非目标

目标（2026-11-15/16 用户确认的连接体验）：
1. **网关连接（B1）**：插件里点「连接 Apercus」→ 打开网关官方授权页（复用门户登录状态）→ 用户允许 → 后台自动完成连接；插件记住登录状态，重开酒馆不重复授权；可退出登录。
2. **key / 模型选择（B3）**：显示账号有哪些 key、选用 key；所选 key 可用的模型直接在插件里选择。
3. **自动接入酒馆（B3/B1）**：选中模型后按酒馆原生连接逻辑自动应用配置；连接成功与否**沿用酒馆状态**，插件不另设判定。
4. **防截断分节（B2）**：预设感知 → 手动生成节名单 → 注入（对接网关 #443/#444 已交付契约）。
5. **计量（B3）**：余额 + 追费阈值 + 上下文用量，沿用网关口径只展示。

非目标：instruct / sysprompt 模板切换检测（只检测 chat 预设）；key 的创建 / 删除 / 重置管理（网关侧 v1 不提供，插件只查与选用）；手填 key 输入框与非 Apercus 服务商地址（插件只服务本网关）；附加参数自由编辑器（酒馆 Custom 源原生能力覆盖）；anthropic / responses 面（保持禁用）；网关侧「已连接插件」列表/单条管理面（留决②已决不纳入；门户「退出所有酒馆插件」批量撤销属 B1，另行纳入）；人工核对码 UI（v3 拍板取消）。

## 1. 切片与验收顺序

### B1 网关连接（依赖 v1.35 连接契约）

流程：面板「连接 Apercus」→ 插件服务端 `POST /api/connect/requests` → UI 打开网关返回的 `authorize_url`（官方授权页，复用门户登录状态；未登录则先登录再回到批准视图）→ 用户在官方页点「允许」（**免输码、免对码**；页内固定提示「如果不是你刚刚在酒馆里发起的，请取消，并在门户『退出所有酒馆插件』断开」，仅告知、不加邮件/核对码/额外步骤；「取消」则请求作废）→ 插件服务端轮询 `POST /api/connect/requests/poll`（≥5 秒间隔，服务端节流）→ `approved` 一次领取 `{login_credential, key, username}` → 保存至 ST 服务端密钥库（secret 命名空间 `apercus_gateway`，JSON `{"version":1,"login_credential":"…","key":"…","username":"…"}`，v1 无签名，按 directories 隔离）→ 面板显示「已授权：`<username>`」（**「已连接」仅在酒馆报告连接成功后显示**，D7）→ 自动进入 key / 模型选择（B3）。

- **保持登录（v3 核心）**：登录凭据持久化；重开酒馆保持已登录，**不重复网页授权**；网关 key 重置后授权关系不断——插件凭登录凭据调 `GET /api/plugin/me/key` 重新取得当前 key 并更新酒馆配置，用户无感。登录凭据 TTL＝滑动 7 天＋**绝对上限 30 天**（2026-11-17/18 拍板）：查询面成功调用自动续期，插件服务端启动探活即完成续期；连续 7 天不用才失效；**签发满 30 天无论活跃与否强制失效**——插件提示重新网页授权（重新点「连接 Apercus」即可）；活跃用户 30 天内无感。插件连接按钮旁与已授权状态显示「登录有效期最长 30 天，到期需重新网页授权；断开插件请到门户退出所有酒馆插件」。**同一账号同时只保留一个插件登录**：在另一设备/实例重新连接会撤销旧登录，旧设备下次查询 401 后需重新连接（2026-11-18 拍板）。
- **退出登录**：面板「退出登录」→ 插件服务端调 `POST /api/plugin/logout`（撤销网关侧本次登录凭据）＋清本地 secret 保存件＋**清除 / 停用 Custom 源接入的网关 key（`api_key_custom`）** → 面板回到未连接态。不影响门户网页登录、不重置网关 key。**门户「退出所有酒馆插件」**另行批量撤销当前账号全部插件凭据（包括已批准未领取请求）；不改 key、不退门户会话，也不承诺终止已交付 key 的数据面；插件下次查询面 401 即转失效态。
- 插件服务端路由（B1 内 4 新 + 1 改；全量汇总见 §2，共 7 新 + 1 改），**安全要求**：全部路由要求 `req.user` 存在否则 401；`POST /connect`、`POST /plan`、`POST /logout`、`GET /connect/status` 校验同源（Origin / `Sec-Fetch-Site`；logout 为状态变更、status 会触发上游轮询，均在列——#452 二轮 H4）；`POST /plan` 加字段白名单、body 上限 16KiB（与网关匿名帽一致）、每用户限频（拟定 6 次/分）；`POST /connect` 响应仅 `{status, authorize_url}`——**浏览器侧只拿 `authorize_url`，任何 secret（polling_secret / login_credential / key）不出服务端**；UI 打开 `authorize_url` 前校验其 host 属固定网关域名，非白名单域拒绝打开（TLS 校验只覆盖服务端调用，不覆盖浏览器跳转）；`GET /connect/status` 响应仅 `{status: connecting|pending|authorized|invalid, username?}`——**永不返回 polling_secret / login_credential / key**；面板渲染的远端字符串（username、key 名称 / 脱敏标识、模型名等）一律 `textContent` / 等价转义，**禁 `innerHTML`**；请求 / 响应体与任何凭据值不落日志；对固定网关域名校验 TLS 证书与主机名。
  - `POST /connect`：发起连接请求；`polling_secret` 与 `request_ref` 只存服务端内存（按 directories 键控）。**连接期状态为按 directories 的单槽内存态**：重复点击复用存活请求（同槽幂等）；服务端重启 / 崩溃 → 状态丢失回未连接态，重新发起即可（pending 行 15 分钟自然过期，#452 二轮 M5）。
  - `GET /connect/status`：服务端节流轮询网关；领取成功即落密钥库并清内存取件件。
  - `POST /logout`：代理网关注销＋清本地。
  - `POST /plan`：B2 代理规划调用。
  - `GET /status`：增授权态（`not_connected` / `authorized` / `invalid`＋失效原因 / `username`）与酒馆连接态 `st_connection`（沿用酒馆自身结果；「已连接」字样仅在此为真时显示），不含开关态。
- **领取失败恢复（consume-once 补强，2026-11-17）**：poll 领取成功后**先写密钥库、写成功才标记 connected**；密钥库写入失败 → 保留内存取件态并自动重试写入（不重新 poll、不重新授权），重试仍失败 → 提示重新连接。`POST /logout` 网关注销失败 → 仍清本地 secret 并转未连接态，提示「远端凭据可能仍有效，可在门户『退出所有酒馆插件』兜底」。
- 失效 UX：查询面 401（凭据过期 / 账号禁用 / 网关撤销 / 门户批量撤销）→ 面板转「登录已失效」，引导重新连接；失效 / logout / 门户批量撤销时**同时清除或停用 Custom 源写入的网关 key（`api_key_custom`）**，避免酒馆仍持可用 key（#452 二轮 H5）；**凭据过期不算异常事件**。酒馆连接模型失败 / 断网 → **沿用酒馆自身状态展示**，不等于退出登录（D7）。
- **启用门控**：未连接或登录失效时，仅连接入口与说明可用；key / 模型选择、防截断开关与注入、规划调用、余额 / 计量数据全部禁用或隐藏。
- 测试：连接状态机（stub 网关：pending / approved / 取消 / 失效联动 / 网络丢失后重连）、领取恰一次、**key 重置→凭登录凭据刷新成功且登录态不变**、logout 后旧凭据 401、门户批量撤销→查询面 401→失效态、跨用户隔离（directories A/B）、无 `req.user` 401、跨源写拒绝、`/connect/status` 载荷不含敏感字段（断言序列化输出）、`POST /connect` 载荷仅 `{status, authorize_url}`、`authorize_url` 非白名单域拒开、密钥库写入失败重试不重 poll、logout 远端失败仍清本地、密钥库写入 fail-closed、`authorized` / 未连接态枚举、服务端重启回未连接态、失效清 `api_key_custom`、登录凭据 30 天绝对上限过期→提示重新授权、`/plan` 白名单外字段拒绝、预设摘要脱敏后发送、登录凭据第 29 天续期不越过 30 天绝对上限、cap=1 重连撤销旧凭据（旧凭据 401、新凭据可用）。

### B2 防截断分节（2026-11-19 整节重写；上游＝v1.32 契约字段＋#444 引擎实测结论，零新契约）

**定位（重设计核心，与产品负责人逐环节讨论定稿）**：预设自带的防截断手段（额度拉满、思维链、"写够字数"）是提示词层软手段——额度耗尽上游照样硬切，一断就是整条回复报废。网关 #442/#443/#444 的机制是硬的：回复强制进工具调用、按节名单拆成 N 次小调用、**逐节交付（流式化，不必等整篇返回的原子工具调用）**、残段抢救；实测首字节 206s→31.6s、每千字成本 0.77µ→0.33µ。插件职责收敛为**喂单**：出题一次、每条消息携带、守卫。**每节字数（800–1000）与逐节交付行为是网关常量（#444 控制语写死；契约注明措辞网关自定、只发上游、不属响应面契约），插件唯一杠杆＝节数与段名**；名单只经 encodeJSON 进控制语字符串——客户端给数据、网关掌提示词。

**① 出题（分节配置器，两次独立调用；预设首次使用或结构层变动时）**——经插件服务端 `POST /plan` 通道（Bearer 当前 key；不走用户当前酒馆连接，天然不与 S喵 等脚本互抢，域名固定在服务端强制；两次调用共用该通道与单一模型选择，未选模型时生成按钮禁用并提示；请求与响应两端不落日志）。**预设摘要生成内置凭据模式脱敏**（常见密钥形态〔`sk-` 前缀、`Bearer `、`key=` / `api_key=` 赋值等〕替换为占位符后再发送；非穷尽，登记为残余接受——预设内容本身会出本机，README 写明，#452 二轮 H7）。参数：`temperature 0.2`、`max_tokens 600`、不带 tools。

  ```
  """
  ```

layers 的键＝输入清单里的条目编号，插件按编号映射回卡片盖结构章——**编号制天然免疫条目重名**（同名条目各盖各的章），也免去模型抄错长 ID 的风险；非法/越界编号按未标注处理（默认 structural）。两次调用的输入预算同为 ≤16000 字符，截掉的部分不进 layers，自然落入默认 structural（保守取向）。

- **校验＝网关契约＋插件自加**（网关约束〔#443 原文〕：有效项 ≥2 才激活分节、≤16 项、单项 ≤64 字节；插件自加严格项：**无重名**——网关对重复节不追溯去重，重名会让按名单回显含混，按失败处理）：**剥代码围栏 → JSON.parse →** 非空数组、无重名、逐项 trim、去空（模型常用 ```json 包裹响应，不剥直接 parse 失败、白耗一次重试）。**任一不满足 → 重试一次 → 仍失败 → 面板报错、防截断保持关闭。无回退、无默认名单**（静默换成通用名单＝假成功＋违背看预设出题的初衷——作废）。
- layers 解析失败 → 重试一次 → 仍失败 → **全部条目按 structural 处理**（保守取向）。

**② 指纹（结构层）**

- **结构层指纹**＝哈希（**启用中 ∩ structural**）的条目内容，管"是否提醒用户重新生成"。调用二对**全部条目（含已关闭）**标层——修复"关闭条目未标注→用户启用时按陌生条目误触发"的缺陷。
- **全量分层指纹**＝哈希**全部条目（含已关闭）的名称＋内容**，只管"何时静默重跑调用二"：与结构层指纹同点惰性比对，不一致 → **静默重跑调用二**（不提醒用户）→ 重算结构层指纹 → 变了才提醒。堵住循环依赖：content 标记的条目内容改成结构要求（字数/格式/固定部件）时不在旧 structural 集合 → 结构层指纹不变 → 没有全量指纹就永远发现不了这次重分类。代价＝每次条目改动（含纯文风）多一次廉价分层调用（max_tokens 600），换漏洞堵死、且用户照样不被文风改动打扰。
- 未标注的条目（新增、layers 缺失、编号非法/越界、被输入截断截掉）一律默认 structural；layers 解析失败全按 structural——两处兜底同一取向：**漏提醒是事故、多提醒只是烦一下，拿不准往多提醒倒**。
- 内容层（文风/人称/情绪/nsfw 风格/纯润色）变化 → 全量指纹变 → 静默重分层，分类不变 → 结构层指纹不变 → **不提醒**（名单是通用阶段措辞、不编码内容层信息）；结构层变化 → 面板黄条提醒重新生成，生成前防截断暂停。
- 事件机制沿用：仅订阅 `PRESET_CHANGED`（过滤 `apiId==='openai'`）驱动提醒与按钮态；两枚指纹惰性计算（注入时与按钮点击时）；指纹未变则提醒自动消退。
- 缓存：`extensionSettings.apercusGateway.sectionsCache[结构层指纹] = {sections, layers, 全量分层指纹}`（明文 JSON 允许；**登录凭据与 key 绝不进 extensionSettings**）。
**③ 注入（每条消息自动；定稿时刻钩子 `CHAT_COMPLETION_SETTINGS_READY`）**

三道闸全过才写 `custom_include_body`：
1. 防截断开关 ON（关＝用户明确不要，安静跳过）；
2. 清单有效（未生成/过期/生成失败 → 不塞＋黄条指引）；
3. 守卫通过（④）＋ 当前对话补全源指向固定网关域名（非网关目标安静跳过——塞了无意义还漏信息）。

写入内容：`apercus_antitrunc: true` ＋ `apercus_antitrunc_sections: [清单]`（请求级指令、无状态，每条消息携带同一份；网关剥两键后把名单插进其控制语常量模板）。max_tokens 地板＝`节数×1200+2000`（#443 契约原文"客户端自担"建议），**不足才提醒＋一键"应用建议值"，不静默改**。`custom_include_body` 写入规则（#452 二轮 H7）：写入前清除本插件旧键；用户已有同名键以用户值为准、不静默覆盖；空串 / 非法 JSON 不写入（合并优先级＝用户字段 > 插件注入）。

**④ 守卫（api.md v1.32 放弃集原文）**

最终请求形态含客户端 `tools`、`functions`、`function_call`、`response_format` 任一／`n` 存在且非字面 `1`／`messages` 缺失·非数组·空 → 网关放弃激活（只剥两键静默透传；`tool_choice` 不在放弃集——网关激活时强制改写成自有工具、客户端值被覆盖，不构成放弃条件）。插件守卫直接检查**打包完的请求形态**（不区分谁开的——预设/脚本/设置一律同罚）：触发 → 不塞＋状态条常驻警告"防截断不生效：检测到函数调用开启"＋仅首次 toast（不逐条弹）。

**⑤ 面板（框架定稿，实现细节交乙侧 Rorollln）**

防截断开关；状态条五态（未生成〔"点击生成开始使用"〕 / 有效 / 过期〔"预设结构已变动，点击重新生成；生成前防截断暂停"〕 / 生成失败〔"点击重试"〕 / 守卫警告〔"检测到函数调用开启"〕）；生成／重新生成按钮（旁注"将消耗少量额度"）；当前清单展示。**开关默认关**。

- 测试：出题两调用成功/格式失败/重试/报错路径；**带代码围栏响应应通过**；校验器全分支（重名、超 16 项、单项超 64B、有效项 <2）；编号映射（越界/非法编号按默认 structural、**重名条目各盖各章**）；结构层指纹（结构层改动触发、新增/缺失条目默认 structural、layers 解析失败全 structural、含关闭条目标层）；全量分层指纹（**content 条目改成结构内容 → 静默重分层 → 结构层指纹变 → 提醒；纯文风改动 → 静默重分层 → 不打扰**）；输入超预算（启用条目优先截断、〔已截断〕标记）；注入三道闸与固定域检查；守卫矩阵（tools/functions/function_call/response_format／n 存在且非字面 1／messages 缺失·非数组·空；**tool_choice 单独不触发**）；max_tokens 地板提醒不静默改；`custom_include_body` 清理（开关关 / 指纹失效 / source 非 custom）、用户同名键优先、预设摘要脱敏后发送；缓存命中不重复调用、按钮禁用态（无模型 / 未连接）。

### B3 key / 模型选择 + 面板计量

- **key 列表与选用（v3 新增）**：`GET /api/plugin/me/keys` 列当前账号有权使用的 key（稳定编号 / 名称 / 脱敏标识 / 状态；**不含明文**；v1 恒一把）；面板展示列表供选用。调用凭据刷新走 `GET /api/plugin/me/key`（凭登录凭据；key 重置后由此恢复，登录态不变）。

## 4. 风险与说明

- **仿冒插件与用户自改（2026-11-18 拍板）**：官方插件**绝不在自身 UI 内收集账号登录凭据**——登录只发生在浏览器内的官方网关页面；任何要求在插件界面内输入账号登录码 / 凭据的版本均为仿冒，README 显著写明。用户自行修改的版本不在官方支持与责任范围内；安全承诺仅覆盖官方发布版本，安装渠道＝本仓发布（P0 README 写明安装来源与仿冒识别）。
- ST 版本漂移：所有事件 / API 特性检测（附录 A 清单），manifest `minimum_client_version` 不动。
- S喵 等社区脚本：README 写明与防截断注入互斥使用；规划调用已隔离在插件服务端。
- 规划调用消耗：按钮旁注明"将消耗少量额度（模型 X）"，失败最多重试一次。
- key 重置联动：网关重置 key → 旧 key 401 → 插件凭登录凭据自动刷新（不要求重新网页授权）；登录凭据自身过期 / 账号禁用 → 「登录已失效」引导重新连接（不做自动重试）。
- 既认残余风险：ST 服务端 secret 命名空间对同机其他 server 插件可读，连接即全量 key 权限（生态既认，v1.35 契约批登记）。
