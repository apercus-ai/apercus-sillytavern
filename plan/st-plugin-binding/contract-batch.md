## 0. 背景与目标

apercus-sillytavern（酒馆插件 = ST UI 扩展 + ST 服务端插件；ST 为自带 Node 服务端的应用，插件服务端可后台工作、可安全持久化）定位＝**用户在酒馆连接网关的便捷入口**。插件只服务 Apercus 网关，不提供其他服务商地址、不提供手填 key 输入框。需要网关支持：

1. **网页授权连接**：插件发起 → 官方授权页（复用门户登录状态）→ 用户允许 → 插件服务端后台领取，免输码、免回调地址配置。
2. **保持登录**：登录凭据与 API key 分离；插件记住登录状态，key 更新不要求重新授权。
3. **key / 模型 / 余额查询**：列当前账号有权使用的 key、所选 key 可用的模型、余额用量与 BILL-08 追费阈值——全部沿用网关现有口径。
4. **退出登录**：插件侧清除＋网关使该次登录失效。

非目标：客户端放行 / 客户端头准入（v0.47 挂账独立批次）；key 的创建 / 删除 / 重置管理（只查与选用，D6）；网关侧「已连接插件」列表/单条管理面（列表仍不入；门户「退出所有」已决入 v1，见 D5/§2.3.1）；`/v1` 数据面任何行为变化；防截断（已随网关 #443/#444 交付，插件侧对接为插件批 B2，不在本批）。

## 1. 决策记录

- **D1 网页授权＋后台领取，免输码免回调。** 插件服务端发起连接请求 → 插件打开网关官方授权页（URL 携带请求引用）→ 用户在页上允许 → 插件服务端凭轮询密钥后台轮询领取。理由：ST 自带 Node 服务端插件（可轮询、可安全持久化）；插件部署形态任意（本机 / 局域网 / 远程），后台领取使网关无需知道也无需校验酒馆返回地址；完整 key 不经 URL、不经浏览器存储。机制形似 RFC 8628 §3.3.1 `verification_uri_complete`（该标准流程仍保留用户码确认、本设计无——差异即具名风险接受，2026-11-18，见 §2.4/§8；类比仅说明「URL 直开授权页」形态，不构成安全等价）。
- **D2 授权状态归网关。** 批准记录、连接关系、凭据发放与撤销全部落在网关库。Pass 只负责「你是谁」：授权页「认出你」借门户会话（现）／Pass（未来），授权账本不随登录方式迁移而迁移（v2 原则保留并升格）。
- **D3 授权页认请求＝URL 携带请求引用；无人工核对码。** v2 的 8 字符用户码、手动输码、逐字比对、禁止 URL 预填整组机制作废（用户 2026-11-15/16 拍板：信任自己部署的酒馆是产品前提，酒馆装错属用户自身问题；人工对码不成为流程必选）。程序层双向校验：插件仅连官方固定网关域名；网关把结果只交付给持轮询密钥的发起方。授权页防「诱导批准」由页面后果全文与网关风控层负责，不以插件交互承担。
- **D4 交付两件套：现有用户 key（一把制）＋插件登录凭据，两者分离。** 批准领取时一次交付 {登录凭据, 当前 key, 用户名}。key 供酒馆连接模型（走酒馆既有保存习惯）；登录凭据供查询面（§2.5）。**授权关系不随 key 变化断开**：key 重置后已签发登录凭据继续有效，插件凭其重新取得当前 key 更新酒馆配置，用户无需重新网页授权（端点见 §2.6 `GET /api/plugin/me/key`）。网关不发明插件专用子 key。**重置 key 不断开插件**——存活登录凭据会取回重置后的新 key（设计取舍：reset 不终止插件凭据，2026-11-17 二轮复审要求写明）；断开插件唯有 revoke-all（D5）。
- **D5 退出登录 ≠ 强制失效，三种结束分开。** 插件退出：清插件侧保存件＋调网关注销端点，仅该次登录凭据失效，门户会话与 key 不动。门户退出所有：`POST /api/portal/me/plugin-credentials/revoke-all`，撤销当前账号全部插件登录凭据（含过期行）＋删除已批准未领取请求（仅 `user_id=当前用户且 expires_at>now`；过期行留惰性清理）；204 幂等；门户会话与 key 不动，不承诺终止已交付 key 的数据面。网关强制失效：账号禁用／凭据过期 → 拒绝后续请求，插件如实显示「登录已失效」引导重新授权；过期不算异常事件。key 重置不自动撤销插件登录凭据。已交付 key 的作废途径＝门户 key 重置（网关**既有已实现**能力：提交即旧 key 失效，首次无冷却、之后 7 天一次，全部门户会话需重新登录）——与 revoke-all 为两步独立操作，不联动、不组合（2026-11-17 用户拍板）。
- **D6 查询面沿用网关现有口径。** key 列表＝当前登录账号有权使用的 key（项：稳定编号 / 名称 / 脱敏标识 / 状态；**不含完整 key 明文**）；模型＝所选 key 有权使用的模型（网关权限判断，插件按酒馆适配能力自行过滤展示）；余额 / 用量 / BILL-08 阈值＝现有口径原样，插件只展示不做计算。v1 无 key 创建 / 删除 / 重置接口。
- **D7 连接成功判定归酒馆。** 插件把网关地址与凭据接入酒馆原生连接机制，状态显示沿用酒馆自身结果；插件不另设「已连接」判定，连接失败不等于退出登录。
- **D8 凭据保存在酒馆服务端，浏览器零保存，多用户隔离。** 与酒馆存 API 设置同一台服务端、同一套持久化习惯；按 ST 注入的 `req.user.directories` 按用户隔离。**插件仓 AGENTS「服务端不写 ST secret」条款随本批修订**（2026-11-16 用户拍板与酒馆保存逻辑一致），实现批核对 ST secrets 实际接口后落地。
- **D9 簿记落库＋哈希分级（v2 D6 思想沿用，实体换名；2026-11-16 修正——v3 免输码设计无低熵码面，v2 的 8 字符 user_code 随重设计废除，HMAC 口径不再需要）。** 连接请求与登录凭据均落库（migration 取当期空号）；`request_ref` / `polling_secret` / 登录凭据均为 CSPRNG ≥128bit 高熵 → 均存普通 sha256（`request_ref` 非秘密但不可枚举，sha256 唯一索引即足）；轮询密钥单次消费（行删除即消费）。
- **D10 横切纪律沿用。** 独立限频器（不与数据面 / 登录桶共用）、三路由 `no-store`、DTO `String()`/`GoString()` 脱敏、日志零码值零凭据、批准＋审计同事务、契约先行＋contractDebt 挂账、门禁清单照旧。

## 2. 契约变更一：连接授权域（新域「连接」，替代 v2「绑定」三操作）

### 2.1 `POST /api/connect/requests` —— 发起连接请求（匿名，插件服务端）

- 请求：`{}`（空对象；拒绝未知字段 422）。v1 不收实例自报名（自报不可信、无身份依据，留决③）。
- 200 响应（`Cache-Control: no-store`）：`{"request_ref": string, "polling_secret": string, "authorize_url": string, "expires_at": <UTC date-time>}`
  - `request_ref`：连接请求引用（CSPRNG ≥128bit URL 安全串），进 `authorize_url` 查询参数（免输码载体；非秘密但不可枚举，库内 sha256 存储，D9）。
  - `polling_secret`：CSPRNG ≥128bit URL 安全串，即取件凭据；TTL 15 分钟，单次消费。
  - `authorize_url`：网关官方授权页绝对地址（路由随 C3 定稿，留决④）。
- 限频：独立限频器；发起按可信 IP 5 次/分；存活请求上限 500，超限 `429 rate_limited`。创建时顺带删除全部过期行（清理先于存活上限判定；计数仅计 `expires_at>now` 行；同事务，无后台清扫器）。poll 桶 30 次/分在全局桶口径下仅支撑约 2 个并发客户端（每客户端 ≥5 秒间隔＝12 次/分），数值随 ops 确认可上调（#452 二轮 H3）。运维注沿用：现部署 `trusted_proxies` 默认为空，「按 IP」实际退化为全局限速，随批提请 ops 知悉。

### 2.2 `POST /api/connect/requests/poll` —— 轮询领取（匿名，凭 polling_secret）

- 请求：`{"polling_secret": string}`；响应 `Cache-Control: no-store`；匿名路由不读取、不记录 portal cookie 与请求头。
- 200 响应：
  - 未批准：`{"status": "pending"}`
  - 已批准（恰一次）：`{"status": "approved", "connect": {"login_credential": string, "key": string, "username": string}}`。同事务 CAS 删行即消费；批准历史由审计行承载。`login_credential` 即 D4 登录凭据（§2.5），与本 key 同事务签发。
- **失效联动（v2 sec 修复语义沿用）**：领取事务按序校验 ①未过期（`expires_at > now`）→ ②账号状态 `enabled` → ③交付 key 与批准时 `key_hash_snapshot` 同源（重算哈希相等）；任一失败 **404 且不消费**（行随 TTL 消亡，插件重新发起即可；进入登录凭据稳态后 key 变化走 §2.6 刷新，不再走本窗口）。效果：批准后、领取前发生 key 重置 / 账号禁用，该次领取拿不到任何 key（含重置后的新 key），防竞态探测。
- 用户在授权页点「取消」→ 删除该无主且未过期行（§2.3 取消端点）；此后 poll 404。404 单一语义不可区分（不存在 / 已消费 / 已过期 / 失效联动 / 已取消），防枚举（v2 原则沿用）。错误序：429 限频先于查库。
- 错误：`404 connect_request_not_found`（新码，逐字登记于 api.md 错误码表）；`422`；`429 rate_limited`（polling_secret ≥5 秒间隔＋可信 IP 30 次/分，独立限频器）；`500`。
- 载体 DTO 带 key 与登录凭据，须实现 `String()`/`GoString()` 脱敏；禁止日志出现请求 / 响应体与任何密钥值。

### 2.3 `POST /api/portal/me/connect/requests/approve` 与 `.../cancel` —— 批准 / 取消（门户会话）

- 鉴权：portal 会话＋精确同源 Origin（沿用 v2 D3）。授权页前端调用；**无人工输码**，`request_ref` 由页面从 URL 取得。
- approve 请求：`{"request_ref": string}`；响应 `{"status": "approved"}`（`no-store`）。
- 行为（CAS）：`UPDATE ... SET user_id=?, key_hash_snapshot=<当前 users.key_hash> WHERE request_ref_hash=? AND user_id IS NULL AND expires_at>now`，`RowsAffected=0` → `404 connect_request_not_found`（未知 / 已批准 / 已过期 / 并发抢批一概同码，恰一 200）。批准不改变 key 本身、不产生 key 新行。
- cancel 请求：`{"request_ref": string}`；行为：`DELETE ... WHERE request_ref_hash=? AND user_id IS NULL AND expires_at>now`（仅无主**且未过期**；过期行留惰性清理、不由 cancel 删），重复调用效果相同（首次删行成功 200，其后 404 同码——状态码不同、效果幂等，#452 二轮 M2 措辞修正）。行已批准 / 已消费 / 不存在 / **已过期** → 404 connect_request_not_found 同码不可区分。取消仅为无主请求的体面出路径，无安全语义。（2026-11-17 按网关契约 connect-0.4 对齐——本稿前版「仅无主含过期行」的统一方向相反，作废。）
- 审计（同事务，沿用 v2 修复）：`admin_id=NULL`、`admin_name="user:<用户名>"`、`object_type="connect_request"`、`object_id=<行 id>`（AUTOINCREMENT 复用防护）、`change_summary` 固定模板含 user_id（users.username 非唯一）、摘要不含任何码值。cancel 不审计（无授权语义）。
- 错误：`401 unauthorized/session_expired`、`403 user_disabled/permission_denied/origin_forbidden`、`404 connect_request_not_found`、`422`、`429 rate_limited`（按用户 10 次/分＋可信 IP 30 次/分，独立限频器）、`500`。
- 并发测试：双 approve 恰一 200；approve 与 poll 消费并发恰一交付。

### 2.3.1 `POST /api/portal/me/plugin-credentials/revoke-all` —— 退出所有酒馆插件（2026-11-16 用户拍板）

- 鉴权：PortalSession＋精确同源 Origin；请求 `{}`（未知字段/非空 422）；成功 204 无 body、no-store、幂等（零变更同样 204）；无 404；不要求二次验密；身份只取会话，不接受自报 user id。403 仅 `origin_forbidden`/`user_disabled`（不涉及 `permission_denied`）；错误序 401/403/422/429/500。
- 限频：与 approve/cancel 共用同一业务桶（按用户 10 次/分＋可信 IP 30 次/分）；SEC-09 守卫失败桶仅 401 计数，403/422 不计。查询面凭据失败桶沿用既有 401-only 口径，不新造数值。
- 行为（同写事务，串行于 poll）：删当前用户全部 `plugin_credentials`（含过期行）；删 `user_id=当前用户 AND expires_at>now` 的已批准未领取 `connect_requests`（过期行留惰性清理；绝不删 `user_id IS NULL` 无主请求）。逐影响对象同事务审计：凭据 `object_type="plugin_credential"`、`action="revoke"`、`object_id`＝真实行 id、摘要 `user_id=<uid>; reason=portal_revoke_all`；请求 `object_type="connect_request"`、`action="revoke"`、`object_id`＝真实行 id、摘要 `user_id=<uid>; scope=approved_unclaimed; reason=portal_revoke_all`。零删除不审计；审计失败整体回滚。不引入审计哨兵、新表或 epoch。
- 并发：poll 的 CAS 删行＋签发同事务；poll 先提交→其新凭据被随后删除；revoke-all 先提交→poll `RowsAffected=0`→404；旧快照写失败不得签发；提交后的新 approve 属新授权，可再次连接。
- 语义：不改 key、不撤门户会话、不改变 `/v1` 数据面；已交付 key 在插件清除或 key 重置前仍可用；插件查询面下次 401 按既定「登录已失效」清除。key 重置不调用本端点、不撤销插件登录凭据。要作废已交付 key，须另行门户 key 重置（既有能力，冷却与影响见 D5）——两操作不联动、不组合。

### 2.4 网关授权页（非契约件，随批实现）

- 打开即读门户会话：已登录 → 直接进入批准视图；未登录 → 先登录（现邮箱码；Pass 迁移后自动切换，契约不可见），登录后回到批准视图。回跳只携带 `request_ref`（免输码机制本体，非 v2 所禁的「凭据预填」）。

- 批准成功页（非契约件，随批实现，2026-11-17 增补）：提示连接已完成，并提供「退出所有酒馆插件」入口（跳转门户对应页面）；除该入口外不留其他管理面（留决②不变）。
- 加固沿用 v2 sec 修复：SPA `Content-Security-Policy: frame-ancestors 'none'` ＋ `X-Frame-Options: DENY`；授权与取消路由 `Referrer-Policy: no-referrer`；授权页响应 `no-store`；严格 CSP（禁 `unsafe-inline`，随 C3 定稿）；回跳仅回授权页固定路径；外链 `noopener,noreferrer`（#452 二轮 H6）。**本节全部项纳入 C1 验收**（虽为非契约件）。

### 2.5 插件登录凭据（connect credential）

- 签发：poll 领取 approved 时同事务生成；CSPRNG ≥128bit URL 安全串；库存 sha256 哈希；簿记对齐现有 `sessions` 表范式（独立簿记；本稿暂名 `plugin_credentials`，表名与列在 C1 冻结后由实现批沿用）。归属 user_id，**与门户会话互相独立**（插件退出不影响网页登录，反之亦然）。
- 使用：作为 Bearer 在 §2.6 查询面鉴权；**不用于 `/v1` 数据面**（数据面仍只认用户 key，两域不混用沿用现库纪律）。**威胁模型注（2026-11-17 二轮复审指明）：登录凭据可经 `GET /api/plugin/me/key` 随时换取完整 key——凭据实际是 key 等价物；「凭据与 key 分离」只提供独立撤销/轮换，不是最小权限。**
- 失效：账号禁用 → 立即拒绝；TTL 到期 → 拒绝（插件提示重新授权，不算异常）；插件调 logout → 即时撤销。**TTL＝滑动 7 天＋绝对上限 30 天（2026-11-17/18 用户拍板，留决①已决）**：每次查询面成功调用自动续期（顺延至最后成功使用＋7 天；插件服务端启动探活即完成续期；实现可按剩余时间节流写，但须保证活跃用户不会因节流提前失效），连续 7 天无成功调用即失效；且**无论活跃与否，签发满 30 天强制失效、必须重新网页授权**——堵住「被窃凭据每 <7 天使用一次即永久续期」的洞（#452 二轮前版残余「滑动无绝对上限」就此关闭）；logout 不续期；不做凭据值轮换。**每用户活跃登录凭据上限＝1（2026-11-18 用户拍板）**：新签发同事务撤销该用户旧凭据并审计 `action=revoke, reason=cap_evict`；多设备/多酒馆需求后续再议。门户 key 重置页须提示「重置 key 不撤销插件登录凭据，断开插件请 revoke-all」（#452 二轮）。
- 网关侧「已连接插件」列表/单条管理面仍不入 v1（留决②已决）；门户「退出所有酒馆插件」入 v1（`POST /api/portal/me/plugin-credentials/revoke-all`，撤销账号全部登录凭据含过期行；204 幂等）；v1 撤销途径＝插件 logout（单条）、门户 revoke-all（全部）、TTL、账号禁用、新签发撤旧（cap=1）；key 重置不自动撤销。

### 2.6 插件查询面（统一登录凭据 Bearer；端点命名终稿留决⑤）

| 端点 | 返回 | 说明 |
|---|---|---|
| `GET /api/plugin/me` | `{username}` | 账号确认（登录状态探活） |

## 3. 契约变更二：BalanceSnapshot 增列（BILL-08 用户侧暴露；v2 内容原样保留）

`GET /api/user/balance`、`GET /api/portal/me/balance` 与 `GET /api/plugin/me/balance` 的 BalanceSnapshot 追加两个**必填**字段（命名与 system_settings KV 键一致）；`GET /api/portal/me` 概览字段集不随批增列：

| 字段 | 形态 | 语义 |
|---|---|---|
| `penalty_input_threshold` | 非负十进制整数字符串 | 大输入惩罚触发阈值 H（token 数）；可信输入 token 数**严格大于** H 才追加费，等于不追加（BILL-08 口径） |

- 两键为 0001 种子 fail-closed 占位、恒有值，故必填；字符串形态与 admin settings 一致（不经浮点，≤MaxInt64）。消费者以 BigInt / 整数校验解析，非法值按「未知」展示。

## 6. 验收口径
